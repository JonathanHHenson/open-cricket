# Open Cricket v0.3.1

Open Cricket v0.3.1 makes Noul prompts more concise and adds a broader set of
ready-to-run CLI examples. Request and response schemas are unchanged from
v0.3.0.

## Clearer Noul prompts

Noul questions now describe their default alternatives as `Yes` and `No`:

```text
A. "true": "Yes"
B. "false": "No"
```

Noul uses the same positional answer codes as Choice and Score. For the default
two alternatives these are `A` and `B`; lowercase model outputs `a` and `b` are
still aggregated into their canonical candidates. No characters are reserved
specifically for Noul.

Explicit `true` and `false` descriptions in Noul criteria continue to replace
the defaults. Answer objects and probabilities retain the existing `noul`
response format.

## More CLI examples

Five example requests have been added alongside the existing support example:

- Product-review sentiment, scoring, and a Noul with custom criteria
- Production incident routing and severity assessment
- Multilingual support classification with Unicode input
- Nested order data with several fulfillment decisions
- A 40-candidate classification that exercises multi-character answer codes

The new [CLI examples guide](../../examples/README.md) includes commands for
running each request and comparing the default answer-code mode with sequence
scoring.

## Upgrading from v0.3.0

No application changes are required. Existing requests, response envelopes,
backend protocols, and scoring modes remain compatible.

If an application relies on the exact text of generated Noul prompts, update its
expectations from the longer generic descriptions to `Yes` and `No`. Custom Noul
descriptions are unaffected.

Development validation passes all **62 tests**, covering the six example files,
Noul prompt rendering, positional and case-insensitive answer codes, local
HF/MLX backends, the SDK, CLI, HTTP API, and LangChain integration.

See the [API reference](../api.md), [SDK guide](../sdk.md), and
[v0.3.0 release notes](v0.3.0.md) for the complete answer-code behavior and
performance measurements.
