# Open Cricket v0.4.0

Open Cricket v0.4.0 adds image inputs to Choice, Score, and Noul questions. It
also supports recent vision-language checkpoints through Hugging Face and MLX,
including Qwen 3.5 and Qwen2.5-VL. Text-only requests keep the existing request
and response shapes; the default checkpoint remains
`Qwen/Qwen2.5-1.5B-Instruct`.

## Image inputs

The CLI, Python SDK, and `POST /v1/systemone` accept an optional top-level
`images` array. Each entry is an image URL, a `data:image/...;base64,...` URL, or
a path readable by the inference process. The same images accompany every
question in the request. The REST API accepts images in its JSON body; it does
not accept multipart uploads. A local path sent over HTTP refers to the server's
filesystem, not the caller's.

```json
{
  "model": "Qwen/Qwen3.5-0.8B",
  "state": "Classify the object in the image.",
  "images": ["examples/assets/red-apple.png"],
  "questions": {
    "object": {
      "type": "choice",
      "criteria": {"apple": null, "banana": null, "other": null}
    }
  }
}
```

`LocalClient.system_one(...)` and the HTTP `Client.system_one(...)` also accept
`images=[...]`. Image requests require a vision-capable checkpoint; text-only
backends reject them explicitly. Server operators should restrict image URLs and
filesystem paths accepted from untrusted clients because the model processor
reads those sources during inference.

## Hugging Face and MLX runtimes

The `hf` extra now uses Transformers 5 and includes image-processing dependencies.
Vision checkpoints load with their processors and multimodal model classes;
text-only checkpoints continue using the causal-LM path. Complete locally cached
Hugging Face models are loaded without a Hub request. A `Loading weights` bar
may still appear while cached weights are read into memory.

On Apple silicon, the `mlx` extra now includes MLX-LM 0.30.7 or newer and
MLX-VLM 0.3.12. Vision checkpoints use MLX-VLM, while text-only checkpoints use
MLX-LM. The bundled compatibility adapters fix image-grid handling for Qwen 3.5,
Qwen3-VL, and Qwen2.5-VL with the pinned MLX-VLM release. MLX vision scoring
recomputes each candidate's full context to keep image and recurrent state
independent across scoring branches; requests with many candidate tokens can
therefore take longer than text-only scoring.

Open Cricket passes `enable_thinking=False` to chat templates because its
classifier scores the immediate next answer token. This matches the default
non-thinking prompt for Qwen3.5-0.8B. It does not remove answer-code bias:
in local comparisons, Qwen 3.5's compact `answer_codes` mode sometimes strongly
favored the first option regardless of its meaning. Use `sequence` mode and
evaluate candidate ordering when testing Qwen 3.5. Qwen2.5 remains the default
text model.

## Try the image example

From the repository root, after installing the chosen runtime extra:

```bash
uv run open-cricket --backend mlx --mode sequence \
  --input examples/apple-image.json --pretty --time
```

The bundled example currently selects `Qwen/Qwen2.5-VL-3B-Instruct`. Use
`--backend hf` with the `hf` extra to run it through Hugging Face, or pass
`--model Qwen/Qwen3.5-0.8B` to try Qwen 3.5. MLX also accepts compatible
vision-capable conversions; a conversion without vision weights cannot process
images.

## Upgrading from v0.3.1

Existing requests may omit `images`; responses and scoring modes are unchanged.
Install or resync the runtime extra you use because the Hugging Face and MLX
dependency versions have changed. Recheck predictions and thresholds when
switching model, precision, runtime, or scoring mode. In particular, image
classification and `answer_codes` versus `sequence` probabilities should not be
assumed equivalent.

Development validation passes all **70 tests**. End-to-end runs with the bundled
apple image returned `apple` and `red` on both Qwen3.5-0.8B and
Qwen2.5-VL-3B-Instruct using MLX; the Qwen3.5-0.8B Hugging Face path also
completed successfully. These are smoke tests, not accuracy benchmarks.
