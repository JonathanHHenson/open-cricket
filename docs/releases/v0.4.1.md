# Open Cricket v0.4.1

Open Cricket v0.4.1 improves image-question performance on Apple silicon and
corrects answer-code prompts for reasoning-capable Qwen models in MLX-VLM.
Request and response shapes remain compatible with v0.4.0.

## Faster MLX image scoring

Qwen2.5-VL answer-code requests now reuse the image and common prompt prefix
across questions, while keeping each question's scoring state independent. On
the bundled `examples/apple-image.json` request with
`Qwen/Qwen2.5-VL-3B-Instruct`, median processing time fell from **1.138 to
0.497 seconds** on the tested Apple Metal setup: **2.29× faster** across seven
alternating runs after warmup. Model loading was excluded. The answers remained
apple and red, and token usage was unchanged.

MLX scoring for Qwen2.5-VL, Qwen3-VL, and Qwen3.5 also computes vocabulary
scores only for answer positions. Sequence scoring combines consecutive answer
positions into one model pass. The shared-prefix optimization applies only when
the image data and a complete image prefix match across questions; other
requests retain independent scoring. See the [benchmark and validation
details](../technical/image-performance.md), or rerun them with:

```bash
python -m examples.benchmark_images --repeats 7
```

Splitting a prompt into a cached prefix and question suffix can change
reduced-precision rounding. On the apple benchmark, the largest probability
change was **1.05 percentage points** on ripeness; the reported ripeness score
changed from 0.950 to 0.955. Recheck thresholds that depend on exact scores.

## Qwen answer-code prompts

MLX-VLM 0.3.12 did not forward `enable_thinking=False` through its chat-template
helper. Open Cricket now applies that setting when rendering the final template,
so reasoning-capable Qwen models score an answer code immediately instead of a
thinking preamble. The fix preserves image placeholders and the existing
non-chat prompt convention. It can change predictions and probabilities for
affected checkpoints. See the [Qwen validation notes](../technical/qwen-answer-codes.md).

## Documentation and upgrading

README links to the license, mascot, and guides now use GitHub URLs so they work
on PyPI. Existing v0.4.0 requests need no changes. If you use MLX with a
reasoning-capable Qwen checkpoint or rely on exact image-question probabilities,
reevaluate predictions and decision thresholds after upgrading.

The development suite passed **73 tests**, including image scoring checks with
real small Qwen model instances on Metal. This note describes repository changes;
it does not by itself publish the package or create a GitHub release.
